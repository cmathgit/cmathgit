### **External AI Model Integration Demo — AP Invoice Intelligence Pipeline**
A proof-of-concept multi-model AI pipeline built inside OIC Gen3 connecting three external AI providers via REST Adapter invokes to perform OCR extraction, semantic embedding, duplicate detection, and AP analyst summarization against vendor invoice PDFs — validating field extraction schema, vector similarity logic, and prompt engineering patterns later migrated to OCI-native services.

##### **What Was Built**
Three capability passes, each using a separate external AI provider:

- **Pass 1 — Plain-Text OCR + Semantic Embedding:** Each invoice PDF is base64-encoded and submitted to an OCR endpoint with a deterministic prompt engineered to return a normalized plain-text string. The normalized string is passed to an embeddings API, producing a semantic vector stored in ATP. Duplicate detection uses cosine similarity via `VECTOR_DISTANCE()` against previously stored invoice vectors.

- **Pass 2 — Structured JSON Extraction:** A second OCR call enforces strict JSON-only output using a prompt that specifies the complete schema. A reusable OIC JavaScript action extracts any nested field from the returned JSON using dot-notation path expressions, enabling clean mapping into OIC flow variables and ATP staging columns. The extracted invoice number drives a downstream ERP lookup to resolve the Oracle invoice ID required for the Payables Attachments REST endpoint.

- **Pass 3 — AP Analyst Summarization:** The structured JSON invoice payload is submitted to a chat completions endpoint via OIC REST Adapter invoke using an AP audit-focused system prompt. The response is extracted and stored in ATP for AP analyst consumption in workflow notifications and email reports.

##### **Observability & Cost Tracking**
All AI service calls are logged centrally, capturing model name, token consumption per step, call latency, per-step pipeline status, and estimated cost per invoice — supporting a daily AI cost summary email. Scoped fault handlers isolate failures at the model call level without aborting the integration.

##### **Why This Demo Matters**
- Validated the JSON extraction schema and field mapping logic used by the production OIC JavaScript function before migrating to OCI Document Understanding as the Oracle-native replacement.
- Proved semantic duplicate detection at the ATP layer using `VECTOR_DISTANCE()` with cosine similarity — a pattern carried forward to OCI Generative AI hosted endpoints.
- Eliminated the vendor index file dependency by demonstrating that invoice metadata can be extracted programmatically from the PDF itself.
- Established provider portability — each external model endpoint is independently replaceable with an OCI Generative AI endpoint by updating the connection target URL and Bearer token, with no orchestration logic changes.

### **Invoice Order Attachment Integration**
An OIC Gen3 scheduled integration that ingests daily zipped invoice image containers from an external supply chain provider via SFTP, extracts invoice metadata directly from each PDF via OCI Document Understanding, stages records in ATP, resolves Oracle invoice IDs through ERP lookups, and invokes the Oracle Fusion Cloud Payables attachments REST API to attach each base64-encoded PDF to its matching invoice record.

##### **Business Problem**
An external supply chain provider sends a daily batch of invoice image ZIP files for EDI-generated invoices. Accounts Payable needs these PDFs attached directly to the corresponding Oracle Financials invoices so that AP staff, auditors, and approvers can view the original image from within the ERP. Without an integration, AP staff manually open each PDF, search for the invoice, and upload the attachment — with no systematic way to track successes, failures, or reprocess with an audit trail.

##### **Technical Design**
A scheduler integration lists ZIP files from the external SFTP and spawns one main integration instance per ZIP. The main integration downloads and unzips the container, stages one ATP record per invoice image, resolves each Oracle invoice ID via a BI Publisher ERP lookup, base64-encodes the corresponding PDF, and posts the attachment payload to the Oracle Payables REST endpoint. Records that fail ID resolution or the REST call are updated to ERROR status with descriptive messages. Orphaned PDFs without matching index entries are surfaced as explicit ATP records rather than silently discarded. Batch-level email notifications include total/success/error counts and a CSV error report for AP follow-up.

##### **AI Enhancement — Invoice Intelligence Layer (OCI-Native)**
An OCI-native multi-model AI pipeline extending the core attachment integration, orchestrated entirely within the OCI compartment boundary using OIC REST adapters, JavaScript actions, and Oracle ATP. All AI calls are governed by a single OCI IAM OAuth2 policy.

- **Document Intelligence & Structured Extraction (OCI Document Understanding):** Each PDF is submitted to the OCI Document Understanding API. The `DOCUMENT_EXTRACTION` feature returns a deterministic, schema-aware structured JSON response for all invoice fields without prompt engineering. A supplemental `OCR` call returns the normalized plain-text string used for embedding. Includes a 5,000-transaction free tier per month; overage at ~$0.010/transaction for extraction.

- **Semantic Embedding & Duplicate Detection (OCI Generative AI — Cohere Embed):** The normalized plain-text invoice string is submitted to the OCI Generative AI embeddings endpoint using the hosted Cohere Embed v4 model. Duplicate detection uses cosine similarity via `VECTOR_DISTANCE()` against previously processed invoice vectors in ATP. On-demand pricing is approximately $0.0002 per invoice.

- **AP Analyst Summarization (OCI Generative AI — Cohere Command R):** The structured JSON invoice payload is submitted to the OCI Generative AI chat endpoint with an AP audit-focused system prompt. The generated summary is stored in ATP for consumption by AP analysts in workflow tasks and email notifications. Approximately $0.00036 per invoice on-demand.

### **SFTP Migration for SCM Integrations: OIC File-Polling Refactor**
Refactored existing SFTP file-polling orchestrations in OIC for SCM integrations to utilize a vendor-hosted SFTP site instead of an on-premises file server. Preserved the existing OIC polling architecture while decoupling from the legacy endpoint.

##### **Business Problem**
A vendor decommissioned an on-premises SFTP server, requiring migration to a vendor-hosted endpoint. Existing outbound integrations relied on BI Publisher schedulers that could not support the new endpoint's non-standard port configuration, creating a delivery gap for scheduled outbound interfaces.

##### **Technical Design**
For inbound flows, an OIC FTP invoke step connects to the new vendor SFTP, downloads files, and writes them to the existing internal SFTP path — preserving all downstream polling, staging, and orchestration logic unchanged. For outbound flows, OIC scheduled orchestrations invoke BI Publisher reports, retrieve output, apply the same file naming and field mapping expected by the external system, and deliver files directly to the new SFTP endpoint. Ad hoc BI Publisher executions are handled by monitoring internal outbound directories for qualifying files and transmitting them through the new path.

##### **Why This Approach Matters**
Minimizes disruption to existing OIC schedules and mappings. Only the upstream SFTP source changes — polling, fault handling, and ESS orchestration remain intact. The boundary-layer toggle pattern is reusable for future partner-hosted SFTP migrations without re-architecting downstream OIC projects.

## Generative AI Full-Stack Engineering & Optimization: BibleVal Benchmark

### Philosophy
Specializing in **cost-optimized LLM deployment**, **RAG architecture**, and **agentic system design**. Advancing secure, cost-effective, and responsible Generative AI through retrieval-augmented generation, multi-agent orchestration, privacy-first prompting protocols, and open-source tooling.

### Executive Summary
Developed **BibleVal**, a novel benchmark demonstrating that free LLM services enhanced with intelligent RAG can **match or exceed premium AI models** while maintaining theological integrity and scholarly rigor. Empirical evaluation demonstrates a **99.6% cost reduction** ($240/year to ~$1.08/year per user) by deploying free LLM services with optimized RAG architecture, matching the A+ theological performance of premium models for biblical exegesis tasks requiring doctrinal precision, linguistic accuracy, and confessional alignment.

**Critical finding:** Embedding model selection proved determinative for theological integrity. `embeddinggemma:300m` maintained Baptist Faith & Message 2000 alignment (A+ grade), while `qwen3-embedding:0.6b` introduced doctrinal compromise (C- grade) by weighting heterodox sources as semantically similar to orthodox queries. This demonstrates that expert RAG engineering — specifically, embedding model evaluation and domain-specific distance metric calibration — constitutes mission-critical architecture, not routine configuration.

**Anti-bias finding:** Contrary to marketing claims from Christian AI platforms, non-Christian LLMs (Claude, GLM, Perplexity Sonar) consistently produced theologically orthodox, BFM2000-aligned exegesis at A+ grade. Meanwhile, a Christian-branded platform underperformed with B- output. Architectural rigor — RAG design, embedding selection, and domain filtering — guarantees theological safety independent of vendor religious identity.
